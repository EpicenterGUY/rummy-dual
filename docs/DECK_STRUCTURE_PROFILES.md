# RUMMY//DUEL — 덱 조합 구조 프로필

## 목적
카드군/테마는 효과 시너지를 고르는 축이고, 조합 구조는 실제 29개 정규 물리 슬롯의 숫자·무늬 분포를 고르는 축이다. 두 축을 분리해 카드군 효과가 맞더라도 손패가 세트/런 어느 쪽도 만들지 못하는 고립 분포를 줄인다.

자동 전투 덱은 항상 **조합 골격 29슬롯 → 네임드/테마 변형 배치 → 조커 1장** 순서로 만든다. 네임드 변형은 원래 물리 슬롯을 바꾸지 않는다.

## 세트형
- 7개 중심 랭크를 네 무늬 모두 채워 28슬롯을 만든다.
- 인접 랭크 1장을 보조로 넣어 총 29슬롯을 맞춘다.
- 목표: 같은 숫자 3장 세트와 네 번째 무늬 BURST 재료가 덱이 줄어든 뒤에도 반복해서 남도록 한다.
- 의도적으로 RUN 창은 적게 둔다.

## 런형
- 두 무늬를 A~K 전 구간으로 채워 26슬롯을 만든다.
- 제3무늬에 3연속 구간을 더해 총 29슬롯을 만든다.
- 목표: 긴 런과 반복 CHAIN 연장 재료가 덱이 줄어든 뒤에도 같은 무늬에 남도록 한다.
- 두 주력 무늬가 같은 랭크를 공유하므로 최소한의 세트 전환 가능성은 남긴다.

## 혼합형
- 한 무늬를 A~K 전 구간으로 채워 런 축을 만든다.
- 4개 간격 랭크를 나머지 세 무늬에도 채워 SET 축을 만든다.
- 두 번째 무늬에 4장의 보조 연속 슬롯을 더한다.
- 목표: 런 축 위의 카드가 동시에 세트의 한 장으로도 쓰이는 `교차 카드`를 확보해 손패 상황에 따라 양쪽으로 전환한다.

## 자동 덱 규칙
1. 플레이어 자동 덱에만 선택한 조합 구조를 적용한다. CPU 자동 덱은 기존 생성 방식을 유지해 난이도 회귀를 피한다.
2. 조합 구조가 29개 물리 슬롯을 먼저 확정한다.
3. 네임드/테마 카드는 그 29슬롯 안에서만 변형으로 들어간다.
4. 한 카드군 자동 편성은 물리 슬롯 기준 최대 4장이다.
5. 나머지 네임드는 캐릭터 행동 경향으로 채우며 자동 네임드 모듈은 기존 9장 규모를 유지한다.
6. 랭크 시작점과 무늬 역할은 매 전투 회전/섞기되어 같은 구조라도 특정 숫자·무늬만 고정되지 않는다.
7. 커스텀 덱은 사용자가 직접 29슬롯을 바꿀 수 있으며, 추천 복원은 현재 선택 구조의 대표 골격을 사용한다.

## 검증 기준
- 모든 프로필은 정확히 29개의 서로 다른 정규 슬롯을 만든다.
- 세트형 6장 표본의 세트 성립률은 RUN형보다 유의하게 높아야 한다.
- 런형 6장 표본의 런 성립률은 SET형보다 유의하게 높아야 한다.
- 혼합형은 세트/런 어느 한쪽으로 과도하게 치우치지 않고, `둘 중 하나` 성립률이 두 전용 구조와 경쟁 가능한 수준이어야 한다.
- 테마를 선택해도 최대 4장 제한과 물리 슬롯 유일성은 유지한다.

최종 승률·러미율·저손패 정체율 수치는 인간 실전/M12 데이터가 쌓인 뒤 조정한다. 2026-09-05부터 일반/연습 전투 저장 샘플에 `playerStructure`와 플레이어별 손패·2/3장 이하·저손패 보호·러미·정비 원시 카운트를 함께 기록하므로 세트형/런형/혼합형 코호트를 같은 로컬 기록에서 직접 비교할 수 있다. 커스텀 덱은 별도 `custom` 코호트로 분리한다.

M12 준비도는 세트형/런형/혼합형 각각 **일반전 v2 표본 10판**을 `1차 비교 가능`, 각각 **20판**을 UI상 `안정권`으로 표시한다. 연습전은 순환 참고값에는 남지만 일반전 승률 준비도에는 포함하지 않는다. 10판 게이트 이후 승률 20%p, 평균 전투 길이 8턴, 2장 이하 비율 10%p, 러미/정비 2회/100턴 이상의 구조 간 범위 또는 전체 재순환 발생을 `추가 확인 신호`로 표시한다. 이 임계치는 통계적 유의성이나 자동 밸런스 합격/실패 기준이 아니라 다음 인간 플레이 점검 대상을 고르는 휴리스틱이다.


## M12 실전 수집 가이드
개발자 패널의 `M12 실전 수집`은 구조별 **일반전 v2** 표본 수만 보고 가장 적게 쌓인 세트형/런형/혼합형을 다음 구조로 추천한다. 동률이면 직전에 플레이한 구조 다음의 부족 구조를 택해 반복 편향을 줄인다. 추천 적용 시 DEV를 끄고 커스텀 덱을 해제하며, 현재 캐릭터와 테마는 유지한 채 일반 대전 준비의 덱 단계로 이동한다. 실제 완료 기록이 기준이므로 추천을 무시하거나 중간에 구조를 바꿔도 다음 추천은 저장된 결과에서 다시 계산된다. 가능하면 같은 캐릭터·테마로 세트형 → 런형 → 혼합형처럼 세 구조를 묶어서 플레이해 효과 테마/캐릭터 차이를 구조 차이로 오인하는 위험을 줄인다.


## M12 테마 × 구조 교차 확인
M12 전투 기록은 구조 안정권 `20/20/20`을 실제로 보존할 수 있도록 최근 **240판**까지 유지한다. 기존 50판 한도는 안정권 최소 60판보다 작아 세 구조가 동시에 안정권에 도달할 수 없는 모순이 있었다.

개발자 패널의 테마×구조 매트릭스는 `mode=battle`, v2 순환 지표 존재, 비커스텀 자동 구조 덱인 표본만 사용해 각 라이브 테마(혼합 포함)를 세트형/런형/혼합형으로 다시 나눈다. 셀에는 표본 수·승률·2장 이하 비율·러미/100턴을 표시한다. 같은 테마의 세 구조 셀이 각각 3판 이상이면 그 테마 안에서 구조별 승률·전투 길이·저손패·러미 범위를 참고값으로 계산한다. 이는 전체 구조 통계에서 보이는 차이가 특정 테마 선택 편중으로 생긴 것인지 확인하기 위한 교차검사이며, 셀당 3판은 통계적 유의성이나 밸런스 합격 기준이 아니다.


## M12 캐릭터 × 구조 보정
캐릭터는 현재 직접적인 전투 패시브가 없고 자동 덱 생성 시 네임드 카드의 성향 가중치만 바꾼다. 따라서 전체 구조 통계가 캐릭터 선택에 따라 흔들린다면 구조 규칙 자체보다 자동 편성된 네임드 구성 차이가 원인일 수 있다.

개발자 패널은 일반전 v2·비커스텀 자동 구조 덱을 유랑자/수집가/회수꾼/광대별로 다시 나누고, 각 캐릭터 안에서 세트형/런형/혼합형의 표본 수·승률·2장 이하 비율·러미/100턴을 표시한다. 같은 캐릭터의 세 셀이 각각 3판 이상이면 승률·평균 전투 길이·저손패·러미의 내부 범위를 참고값으로 표시한다. 이 값은 캐릭터 성향으로 생긴 덱 구성 편향을 찾는 보정 신호이며, 셀당 3판은 유의성/합격 기준이 아니다.


## M12 캐릭터 + 테마 균형 매칭
테마별 표와 캐릭터별 표를 따로 보는 것만으로는 `특정 캐릭터가 특정 테마와 함께 한 구조에 몰린 경우`의 결합 교란을 완전히 제거하지 못한다. 그래서 일반전 v2·비커스텀 자동 구조 덱을 `playerChar + playerTheme` 컨텍스트로 묶고, 각 컨텍스트에서 세트형/런형/혼합형 중 가장 적은 셀 수를 기준으로 세 구조에서 같은 수의 **최근 표본**만 취한다. 이 균형 표본을 컨텍스트 전체에서 합쳐 구조별 승률·평균 턴·2장 이하·러미/100턴을 다시 계산한다.

예를 들어 한 컨텍스트가 세트 5 / 런 2 / 혼합 4판이면 각 구조의 최근 2판씩만 매칭 풀에 들어가며 이 컨텍스트는 2개 매칭 블록을 기여한다. 개발자 패널은 원시 전체 승률 대비 매칭 승률 이동도 함께 보여 구성 편중이 구조 통계를 얼마나 움직이는지 확인한다. 매칭 블록 3개는 관찰 시작점일 뿐 통계적 유의성 기준이 아니다. 실전 수집 추천은 전체 10/20판 구조 게이트를 우선하되, 전체 표본 수가 동률인 후보끼리는 현재 캐릭터+테마 컨텍스트에서 덜 쌓인 구조를 먼저 추천한다.
