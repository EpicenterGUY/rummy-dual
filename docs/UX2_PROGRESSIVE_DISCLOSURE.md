# 일반 UI / DEV UI 분리

구현 기준: 2026-09-02. 기존 단일 파일 게임 엔진과 v8 로그라이크 저장을 재사용한다.

## 일반 진입 구조

메인에는 **대전 / 로그라이크 / 튜토리얼 / 카드 도감 / 설정**만 노출한다. 선택이 필요한 시점에 해당 화면을 여는 progressive disclosure 원칙을 적용한다.

| 진입 | 현재 화면 흐름 |
| --- | --- |
| 대전 | 캐릭터 → 덱 방향 → 대전 시작. 직접 덱 편집은 덱 방향 화면에서 선택적으로 펼친다. |
| 로그라이크 | 계속하기 / 새 게임 / 기록. 새 게임은 스타터 → 초기 구성 확인 → 공통 시작 전투로 이어진다. |
| 튜토리얼 | 기본 / 고급 / 자유 연습 / 테마 체험 / 규칙·용어. 고급·테마 체험의 기존 완료 조건은 유지한다. |
| 카드 도감 | 전체 / 해금 / 무늬·조커·필드 / 라이브 카드군 / 랭크 필터. 개발 중 카드군과 내부 태그는 숨긴다. |
| 설정 | 모션 줄이기 / 설명 글자 크게 / 튜토리얼 재안내. 개발자 작업실은 별도 하위 진입이다. |

메인의 캐릭터·해금, 고급 튜토리얼, 테마 체험, 자유 연습, DEV 독립 버튼을 제거했다. 일반 전투 중 메뉴는 도감·설정·규칙·메인으로 구성하고, DEV 전투에서만 DEV 제어를 추가한다. 표시 설정은 실제 CSS와 카드 이동·전투 효과 생성에 적용하며 기기의 모션 감소도 존중한다.

## 로그라이크 단계

- **계속하기**는 저장된 현재 전투, 미처리 보상 또는 지역 선택을 연다. 전투 도중의 손패를 저장하는 기능을 새로 추가한 것은 아니다.
- **새 게임**의 스타터 선택과 초기 구성 확인은 저장을 바꾸지 않는다. 진행 중인 런을 바꾸려면 마지막 확인 화면의 동의를 받아야 하며, 다른 런으로 바뀐 오래된 확인은 거부한다.
- 전투 전에는 현재 상대·공용 필드만 안내한다. 공통 시작에서는 첫 전투 안내만 보여 준다.
- 승리 후에는 고정된 후보 중 카드 선택 → 같은 숫자·무늬의 교체 확인 → 수령, 또는 건너뛰기를 제공한다. 선택 취소는 보상을 소비하지 않는다.
- 보상을 처리한 후에만 다음 전투나 미방문 지역 선택이 열린다. 지역 선택을 메인 메뉴로 노출하지 않는다.
- 런 지도는 진행 화면에서 필요할 때 펼치는 읽기 전용 보기다.
- 최종 보상 저장 후 완료 런을 자동 보관한다. **기록**에서 최근 24개 완료 런의 경로, 수령/건너뛰기, 최종 덱을 펼쳐 볼 수 있다.
- 아카이브 저장 실패는 이미 저장한 런 완료를 되돌리지 않는다. 기록 화면에서 재시도하며, 완료 런을 새 런으로 대체하기 전에는 보관 성공을 확인한다.

14전투·보상·지역 선택·런 완료의 기존 계약을 유지한다. 상점·이벤트·엘리트의 실제 노드 연결은 기존 M11A 미완료 범위다.

## DEV 작업실

설정 → 개발자 작업실 → DEV 샌드박스 켜기에서 진입한다. 같은 캐릭터·덱 편집 컴포넌트를 DEV 호스트로 옮겨 재사용하며, 일반 화면과 중복된 편집기를 만들지 않는다.

- 전체 구현 카드·캐릭터·필드 해금 우회, 개발 중 카드군 선택, 52슬롯 덱 구성.
- DEV 새 대전의 공용 필드 강제 선택. 고정 필드를 사용하는 로그라이크 적·M11B 실험의 시나리오 계약은 그대로다.
- DEV 런 스타터·지역 진행·수동 보상 노드 발급·교체·건너뛰기·런 덱 실험.
- DEV 선택·진행도 사본 초기화. 일반 진행도를 초기화하는 버튼은 제공하지 않는다.
- M11B 0/4/10장 실험, 비교 시드, 실험 기록과 기존 전투 지표 조회·내보내기.
- DEV 도감은 개발 중 필터, 실제 해금과 우회 공개의 구분, 카드 ID / themeId / 효과 tag를 표시한다. 정의가 없는 후보 카드를 구현된 카드처럼 생성하지 않는다.

DEV 작업실의 상태 바, DEV 도감 제목, 전투 상단의 독립 배지와 결과 배지로 세션을 표시한다. 모바일에서 일반 캐릭터 배지가 숨겨져도 DEV 배지는 남는다. 일반 메뉴 복귀·재실행은 항상 일반 모드이며, DEV 캐릭터·테마·덱 선택은 다음 DEV 진입 시 전용 사본에서 복원한다.

## 저장 경계

| 데이터 | 일반 | DEV |
| --- | --- | --- |
| 캐릭터·테마·덱·클리어·튜토리얼 | `rummyDuelProgressV25` | `rummyDuelDeveloperProgressV1` |
| 현재 런 | `rummyDuelRoguelikeRunDraftV1` | `rummyDuelDeveloperRunDraftV1` |
| 완료 런 | `rummyDuelRoguelikeRunHistoryV1` | `rummyDuelDeveloperRunHistoryV1` |
| 표시 설정 | `rummyDuelSettingsV1` | 플레이어 표시 설정을 공유 |

DEV를 켤 때 일반 progress 객체를 보관하고 별도 정규화 사본을 사용한다. 끌 때 원래 객체를 복원하며 DEV의 선택이나 덱 변형을 일반 저장에 덮어쓰지 않는다. 기존 DEV 플래그가 저장되어 있어도 자동으로 DEV 대전을 시작하지 않는다. 과거 버전에서 일반 저장에 남은 잠긴 캐릭터/개발 테마 선택은 유랑자/혼합으로 되돌리고 클리어·레벨은 보존한다.

`developerBattle`은 시작 시점의 세션을 기록하며 로그라이크 실전 노드에도 유지된다. DEV 일반전은 클리어·레벨·해금 및 M12 기록을 남기지 않고, DEV 로그라이크 승리·보상·완료는 DEV 런 저장에만 반영된다. 런 ID·노드·revision·덱 지문 검증과 오래된 결과 거부는 기존 엔진을 그대로 사용한다.

## 검증

- `node tests/ux2-menu-isolation.mjs`: 일반/DEV 각각 14전투 완료, 보상 중복·오래된 결과 거부, DEV 프로필·덱·필드 격리, 일반 진행도 유지, 완료 아카이브·삭제 격리, 저장 실패, 정상 대전 보상, 설정 저장·도감 분리를 실행 검증한다.
- 기존 메뉴 문구/위치 회귀를 현재 화면 구조에 맞춰 갱신했다. 전투·튜토리얼·런 엔진을 포함한 `tests/*.mjs` 전체 126개가 통과했다.
- `/qa/ui`: 실제 페이지를 같은 출처 iframe에 렌더링하는 개발용 검사 화면. 각 시나리오는 메모리 저장을 사용하며 플레이어 저장에는 접근하지 않는다.
- `UX2_LAYOUT_RESULTS.json`: 51개 화면·크기 조합. 360×640, 360×800, 390×844, 480×900, Fold 펼침 852×744, 태블릿 768×1024·1024×768, 1366×768, 1920×1080에서 메인·로그라이크 첫 메뉴·DEV를 확인했다.
- 모든 측정에서 문서/패널 가로 넘침과 컨트롤 잘림 0. 메인과 로그라이크 첫 메뉴의 추가 세로 스크롤 0. DEV는 내부 스크롤을 허용하며 버튼은 최소 40px이다. 긴 보상 설명·덱 편집·도감은 가독성을 유지하며 스크롤한다.
- 실제 버튼으로 새 런 선택 → 초기 구성 → 첫 전투, 보상 선택 → 교체 확인 → 다음 전투, 표시 설정 변경, 일반 도감 Q 필터와 360px DEV 전투 배지를 확인했다.

이는 Chromium CSS 뷰포트 검사다. 실제 Fold 힌지·안전 영역, 모바일 브라우저 주소창·운영체제 글자 확대의 실기기 검증은 별도로 남는다.
