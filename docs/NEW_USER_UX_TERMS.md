# RUMMY//DUEL 신규 유저 UX · 튜토리얼 · 한국어 용어 설계

기준: 2026-08-30 `main` (`dda7c05f3f255062d78ce46fcc385135929448d5`)

이 문서는 신규 시작창/튜토리얼과 사용자 노출 용어를 구현하기 전의 공식 설계 기준이다. 실제 규칙/엔진은 `main`의 현재 동작을 우선하며, 튜토리얼 때문에 별도의 가짜 규칙을 만들지 않는다.

## 1. 현재 상태 분석

### 시작 진입
- 현재 별도의 시작 화면이 없다.
- 페이지 로드 마지막에 `renderProgress(); newGame();`가 실행되어 즉시 랜덤 전투를 생성한다.
- 상단에는 `캐릭터·해금`, `도감`, `규칙·용어`가 있고 각각 기존 오버레이를 연다.
- 따라서 신규 시작창은 새 게임 규칙을 만드는 작업이 아니라, **기존 오버레이와 `newGame()` 진입을 정리하는 앱 셸/라우팅 작업**으로 설계한다.

### 현재 전투 엔진에서 재사용할 핵심 경로
- 게임 생성: `newGame()`
- 카드 생성/덱: `makeCard()`, `makeDeck()`
- 턴 시작/종료: `turnStart()`, `turnEnd()`, `endPlayerTurn()`, `aiTurn()`
- 조합 판정: `setValid()`, `runValid()`, `meldType()`
- 새 조합: `submitNewMeld()`
- 붙이기: `attachCards()`
- 스위치: `canSideReturn()`, `returnSwitch()`, `setSwitchTarget()`
- 누적 위력/폭발: `addSwitchPower()`, `detonate()`
- 러미: `triggerRummy()`
- 회수: `canRecoverCard()`, `playerRecover()`, `executeRecoverAI()`

튜토리얼은 위 함수들을 복제하지 않고 그대로 통과해야 한다.

### 저장
현재 저장 키는 `rummyDuelProgressV25`이며 `totalClears`, `selectedChar`, 캐릭터별 진행도를 저장한다. 튜토리얼 완료 여부는 별도 저장소를 새로 만들기보다 기존 progress 스키마를 하위 호환으로 확장하는 것이 우선이다.

권장 추가 필드:
- `tutorialPromptSeen: boolean`
- `tutorialCompleted: boolean`
- 필요해질 때만 `tutorialLastStep: string | null`

기존 저장을 읽을 때 필드가 없으면 `false`로 정규화한다.

### 모바일
현재 UI는 `width:min(100vw,480px)`, `100dvh`, `touch-action:manipulation` 기반이며 390px 이하 전용 조정도 이미 존재한다. 시작창/튜토리얼도 이 480px 모바일 우선 셸을 그대로 사용한다. 별도 데스크톱 전용 레이아웃을 먼저 만들지 않는다.

### 요청안과 현재 규칙의 충돌
튜토리얼 STEP 1에서 “카드 1장을 필드에 배치”하는 식의 조작은 현재 기본 규칙과 맞지 않는다. 현재 새 조합은 **정확히 3장의 세트/런**으로만 시작한다. 따라서 기본 조작 단계는 `획득 → 손패 선택 → 새 조합/붙이기/정비/버리기`의 UI를 익히는 단계로 바꾸고, 실제 공개 조합 생성은 SET/RUN 단계에서 수행한다.

## 2. 신규 시작창 최종 구조

### 1차 메뉴
1. **대전 시작** — 현재 일반 `newGame()` 진입. 구현 즉시 활성.
2. **튜토리얼** — 튜토리얼 프레임워크 구현 후 활성.
3. **카드 도감** — 기존 도감 오버레이를 재사용하므로 시작창 도입 시 바로 연결 가능.
4. **설정** — 실제 설정 기능이 생기기 전에는 `준비 중`으로 비활성. 존재하지 않는 설정 화면을 가장하지 않는다.

보조 진입은 작은 링크/버튼으로만 둔다.
- `캐릭터·해금` — 기존 진행도 오버레이 재사용.
- `규칙·용어` — 기존 규칙 오버레이 재사용하며 용어 통일 작업 이후 텍스트 갱신.

아직 없는 `덱 편집`, `테마군`, `V-SIGNAL 체험전`은 시작창의 활성 메뉴로 만들지 않는다. 덱 편집은 M11 이후, 테마군 메뉴는 실제 테마 콘텐츠가 코드에 존재한 뒤 추가한다.

### 화면 원칙
- 첫 화면에는 로고, 한 문장 소개, 4개 핵심 메뉴만 우선 노출한다.
- 규칙 장문은 시작창에 넣지 않는다.
- 현재 `FINAL CORE 2.0`, `3 CORE SWITCH RALLY` 같은 개발/버전성 영문 문구는 메인 카피에서 내리고 필요하면 작은 버전 정보로만 남긴다.
- 추천 한 문장: **“세트와 런으로 폭탄을 키워 스위치를 넘기는 1:1 러미 배틀.”**

## 3. 첫 실행 UX

처음 실행했으며 `tutorialPromptSeen === false`일 때 시작창 안에서 한 번만 가볍게 제안한다.

> RUMMY//DUEL이 처음인가요?
>
> [튜토리얼 시작] [바로 대전]

- 강제 진입 금지.
- `바로 대전`을 눌러도 `tutorialPromptSeen=true`만 저장하고 `tutorialCompleted`는 그대로 둔다.
- 시작창의 `튜토리얼` 메뉴와 `규칙·용어`에서는 언제든 다시 볼 수 있다.
- 완료 후 `tutorialCompleted=true`.

## 4. 튜토리얼 기술 구조

### 기본 원칙
**실제 게임 UI + 실제 엔진 + 고정 상태 + 행동 제한** 구조로 만든다.

권장 구조:
- `sessionMode: 'battle' | 'tutorial'`
- `TUTORIAL_STEPS`: 단계 데이터
- `startTutorial(stepId)`
- `applyTutorialScenario(step)` — `makeCard()`로 고정 손패/덱/공개 조합/스위치 상태 구성
- `tutorialAllows(action, context)` — 현재 단계에서 허용되지 않은 행동만 부드럽게 차단
- `tutorialCheckProgress(event, context)` — 실제 엔진 행동 성공 뒤 자동 다음 단계
- `renderTutorialCoach()` — 짧은 목표/힌트/종료/다시 보기 UI

규칙 함수의 튜토리얼용 복제(`tutorialSetValid`, `tutorialAttachCards` 등)는 만들지 않는다.

### 고정 덱/상태
튜토리얼에서는 `makeDeck()`의 랜덤 결과를 쓰지 않는다. 필요한 카드를 `makeCard()`로 직접 배치한다. 일반 전투에 돌아오면 기존 랜덤 덱/필드 로직을 그대로 사용한다.

튜토리얼 1차에서는 순수 카드 위주로 구성하고 네임드/테마군은 배제한다.

## 5. 튜토리얼 단계 최종안

### STEP 1 — 기본 조작
목표: 손패 선택, 카드 획득/버리기, 실행 버튼/공개 조합 영역의 위치를 익힌다.

- 단일 카드를 보드에 내는 가짜 규칙은 만들지 않는다.
- 짧은 안내 후 실제 SET 단계로 자연스럽게 연결한다.

### STEP 2 — 세트
고정 손패 예: `3♠ / 3♥ / 3♦`.

안내:
> 같은 값의 카드 3장을 서로 다른 무늬로 모으면 **세트**를 만들 수 있습니다.

성공 시 해당 공개 조합을 강조하고 `버스트 준비`를 보여준다.

### STEP 3 — 런
고정 손패 예: `4♣ / 5♣ / 6♣`.

안내:
> 같은 무늬에서 값이 연속되면 **런**을 만들 수 있습니다.

A-2-3 / Q-K-A 같은 특수 가장자리 규칙은 기본 단계에서 장문 설명하지 않고 규칙·용어에 둔다.

### STEP 4 — 붙이기
- 이미 존재하는 내 런에 카드를 붙이는 예시 1회.
- 다음 장면에서는 **상대 공개 조합에도 조건이 맞으면 붙일 수 있음**을 반드시 체험시킨다.
- 실제 `attachCards()` 경로 사용.

안내:
> 조건이 맞는 카드는 이미 공개된 조합에 **붙일 수 있습니다.** 상대 조합도 이용할 수 있습니다.

### STEP 5 — 스위치
고정된 중립/자기 대상 상황을 사용한다.

반드시 체험할 내용:
- 스위치는 “폭탄 그 자체”가 아니라 **현재 누적 위력의 폭발 위험이 누구를 향하는지** 나타낸다.
- 중립 또는 자신을 가리킬 때 버스트/체인으로 상대에게 넘긴다.
- 한 턴 기본 반환은 1회.

안내:
> **스위치**가 나를 가리키면 내 턴 종료 전에 상대에게 넘길 방법을 찾으세요.

### STEP 6 — 누적 위력 / 폭발
고정 상태로 스위치가 플레이어를 가리키게 하고, 반환하지 않은 턴 종료를 직접 체험시킨다.

안내:
> 스위치가 나를 가리킨 채 턴을 끝내면 누적 위력이 **폭발**해 현재 코어에 피해를 줍니다.

현재 규칙 그대로 보호막 → 현재 CORE → 초과 피해 소멸을 사용한다. 초보 단계에서는 수식보다 결과 피드백을 강조한다.

### STEP 7 — 러미
손패가 1~3장 남은 고정 상태로 시작해 모두 사용하게 한다.

안내:
> 손패를 모두 사용하면 **러미!** 새 손패 6장을 받고 플레이를 이어갑니다.

실제 `triggerRummy()` 사용. 플레이어 러미는 현재 행동 처리 후 새 손패를 받고 턴이 종료되는 실제 흐름을 유지한다.

### STEP 8 — 자유 연습전
- 튜토리얼 전용 고정 시작 덱.
- 초기 몇 드로우만 고정하고 이후 일반 흐름을 허용.
- 상대는 약한 스크립트 AI 또는 기존 AI의 낮은 위험 선택을 사용.
- 승패보다 세트/런/붙이기/스위치/러미 재사용이 목표.

회수, 정비, 네임드, 상태, 조커, 테마군은 고급 튜토리얼 후보로 분리한다.

## 6. 튜토리얼 하이라이트 UX

- 현재 목표 카드: 테두리/미세 펄스.
- 현재 목표 조합: 기존 `target`/`validAttach` 시각 언어 재사용.
- 스위치: 기존 `switchAlert`, `selfThreat`, 전투 배너 재사용.
- 성공한 세트/런: 기존 `burstReady`, `chainHot` 스타일 재사용.
- 설명 패널: 화면 아래 고정형 또는 현재 행동 영역 바로 위. 카드/공개 조합을 덮는 중앙 모달 금지.
- 잘못된 행동: 상태를 망가뜨리지 않고 한 줄 힌트만 표시.
- 행동 성공 시 자동 진행. `다음` 버튼은 설명 재확인이 필요한 구간에만 사용.
- `[힌트 다시 보기]`, `[튜토리얼 종료]` 제공.

## 7. 한국어 용어 조사 결과

현재 사용자 화면/규칙/전투 피드백에는 다음 영문 또는 한영 혼용 표현이 핵심적으로 남아 있다.

- SET / RUN
- BURST / BURST READY
- CHAIN / NEXT / TOTAL
- SWITCH / SWITCH RALLY
- RUMMY
- DETONATE
- OVERLOAD
- CORE / CORE BREAK / CORE LETHAL
- OVERKILL LOST / NO PIERCE
- YOU / PLAYER / CPU
- FINAL CORE 2.0
- POWER
- FIELD
- NEW UNLOCK / VICTORY / DEFEAT 등 일부 결과/표시 문구

반대로 덱, 손패, 버림패, 뽑기, 회수, 정비, 보호막, 피해, 효과 등은 이미 대체로 자연스러운 한국어/정착 외래어를 사용한다.

## 11. 카드 효과문 문체

사용자 노출 카드 효과는 **조건 → 효과** 순서의 서술형을 우선한다.
- 의무적으로 처리하는 효과는 `~한다.`, `~얻는다.`, `~뽑는다.`, `~증가한다.`처럼 문장을 끝낸다.
- 플레이어가 선택할 수 있는 효과만 `~할 수 있다.`를 사용한다.
- 수치는 명사만 남기는 축약형보다 `보호막 12를 얻는다.`, `누적 위력이 10 증가한다.`처럼 무엇이 변하는지 적는다.
- `카드 1장을 뽑는다.`처럼 대상과 수량을 가능한 한 함께 적는다.
- `턴당 1회.`처럼 단독 제한 문구를 두기보다 `턴당 1회만 발동한다.`처럼 문장으로 적는다.
- 여러 효과는 `~하고`, `~한 뒤`, `~라면`으로 해결 순서를 드러낸다.

피한다:
- `ATTACH 시 DRAW 1`
- `SWITCH 획득`
- `RUMMY 후 DRAW`
- `DETONATE DAMAGE -15`

세트/런/버스트/체인/스위치/러미처럼 공식화된 외래어/고유어는 한국어 표기로 문장에 넣는다.

## 12. 코드 내부 명칭 유지 원칙

이번 현지화에서 다음과 같은 내부 식별자는 특별한 이유가 없으면 변경하지 않는다.
- `setValid`, `runValid`, `meldType`
- `submitNewMeld`, `attachCards`
- `switchTarget`, `switchPower`, `returnSwitch`
- `detonate`, `triggerRummy`
- `CORE_HP`, `OVERLOAD`
- 카드 `tag`, `id`, 상태 key
- 테스트 파일의 내부 함수/키 참조

한국어 통일 대상은 **UI 문자열, 카드 설명, 튜토리얼, 규칙/도움말, 시작창**이다.

## 13. 구현 순서

### 선행: 용어 잠금
1. 이 문서의 용어집을 기준으로 사용자 노출 핵심 용어를 확정.
2. 기존 규칙창/전투 UI/카드 설명의 영문 대문자 표현을 조사하고 치환 테스트 추가.
3. 코드 내부 이름은 유지.

### P1 — 신규 유저 진입
1. 시작 화면 앱 셸 추가. 로드 시 `newGame()` 자동 실행 제거.
2. `대전 시작 / 튜토리얼 / 카드 도감 / 설정(준비 중)` 구성.
3. 기존 캐릭터·해금/도감/규칙 오버레이 연결.
4. progress에 튜토리얼 플래그 추가.
5. 첫 실행 튜토리얼 제안.
6. `sessionMode` + `TUTORIAL_STEPS` + 고정 상태 생성기 구축.
7. 기본 조작, 세트, 런, 붙이기, 스위치, 러미 단계 구현.

### P2 — 완성도
1. 누적 위력/폭발 체험 강화.
2. 자유 연습전.
3. 튜토리얼 재시작/종료/다시 보기.
4. 행동 성공 자동 진행과 하이라이트/연출 보강.
5. 390px 이하 터치/잘림 회귀 점검.

### P3 — 확장
1. 회수/정비/상태/조커 고급 튜토리얼.
2. 네임드 카드 설명.
3. 테마군 소개/체험전.
4. V-SIGNAL은 실제 테마 카드가 코드에 들어온 뒤 별도 고급 체험으로 추가.

## 14. 구현 시 금지 사항

- 튜토리얼만 통과하는 별도 SET/RUN/SWITCH 판정 함수를 만들지 않는다.
- 아직 없는 덱 편집/설정/테마군 화면을 활성 기능처럼 노출하지 않는다.
- 튜토리얼을 위해 일반 규칙을 단순화한 뒤 그것을 실제 규칙처럼 설명하지 않는다.
- 긴 규칙 문장을 시작 화면에 쌓지 않는다.
- 영문 내부 함수명을 한국어로 일괄 리네임하지 않는다.
