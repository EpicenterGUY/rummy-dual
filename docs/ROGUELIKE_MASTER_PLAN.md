# RUMMY//DUEL — Roguelike Master Plan (Working Draft)

Updated: 2026-09-02

이 문서는 RUMMY//DUEL의 로그라이크 확장에 대해 현재까지 논의한 **캐릭터/스타터, 순수카드, 테마군, 지역, 카드 보상, 런 구조**를 한곳에 보존하는 작업용 설계안이다.

중요: `FINAL CORE 2.0`의 전투 규칙을 바꾸는 문서는 아니다. 아래에서 **v1 잠금**으로 명시한 스타터 30장 구조, 순수/네임드 비율, 직접 전투 패시브 없음, 캐릭터 보상 후보 랭킹 가중치는 현재 구현 기준으로 고정한다. 실제 보상 등장 확률, 카드 희귀도, 지역 수, 런 경제와 PURE 전용 특전은 플레이테스트 이후 조정한다.

## 1. 로그라이크의 핵심 방향

- 완성된 테마덱을 고르고 시작하는 구조보다 **스타터가 방향만 제시하고 런 도중 덱이 변하는 구조**를 우선한다.
- 기본 흐름 후보는 `스타터 선택 → 공통 시작 구역 → 지역 분기 → 지역별 카드풀/이벤트 → 중간 보스 → 추가 지역 선택 → 후반 특수구역 → 최종 보스`다.
- 순수 트럼프가 덱의 뼈대이며, 네임드 카드는 숫자/무늬 구조 위에서 규칙을 비튼다.
- 테마군은 서로 섞일 수 있어야 하며, 지역 선택은 특정 테마를 강제하기보다 해당 플레이스타일의 등장 확률을 높인다.
- 같은 스타터라도 런 후반에는 시작과 전혀 다른 혼합덱이 될 수 있어야 한다.

## 2. 캐릭터 / 스타터 방향

캐릭터는 특정 카드군만 사용할 수 있는 클래스가 아니라 **런의 출발 방향**이다.

후보 요소:

- 순수 트럼프 다수 + 해당 성향의 효과카드 소수
- 특정 행동 또는 지역/테마 카드 보상 가중치
- 작은 고유 패시브 또는 시작 유물
- 다른 테마 및 다른 지역 카드 획득은 항상 허용

캐릭터 선택만으로 완성 콤보를 지급하지 않는다. 예를 들어 V-SIGNAL 성향 캐릭터로 시작해도 런 중 ZERO-SIGHT, MAIL-ROUTE, POINT-BLANK 등으로 자유롭게 전환하거나 혼합할 수 있다.

v1 잠금 항목:

- 모든 스타터 시작 덱은 30장 = 정규 슬롯 29 + 조커 1.
- 유랑자/수집가/회수꾼/광대는 순수 23 + 네임드 정규 6 + 네임드 조커 1.
- PURE는 순수 정규 29 + 기본 와일드 조커 1이며 네임드/효과카드 0장.
- 직접 전투 패시브는 전원 없음. 스타터 차이는 시작 네임드 구성과 보상 후보 랭킹으로 만든다.
- 보상 후보 랭킹은 현재 `CHARACTERS.weights`를 그대로 쓰는 `character-tendency-score-v1` 소프트 가중치다. 가중치는 후보 점수에만 관여하고 다른 카드군을 금지하지 않는다.

계속 미확정인 항목:

- 6개의 시작 네임드 정규 슬롯에 들어갈 실제 카드 ID와 네임드 조커의 스타터별 세부 선택 규칙
- 실제 보상 등장 확률 / 희귀도 / 전투 등급별 경제
- 캐릭터와 지역의 관계
- PURE 전용 외부 특전/유물

## 3. PURE — 온리 순수 스타터

`PURE`는 별도 테마 카드군이 아니라 **효과카드 0장으로 시작하는 백지형 스타터/빌드 경로**다.

방향:

- 모든 시작 카드는 효과 없는 순수 트럼프.
- 숫자/무늬 분포는 v1에서 공통 정규 29슬롯 `S3,S4,S5,S6,S7,S8,S9,H2,H3,H4,H7,H8,H9,D2,D3,D4,D5,D6,D7,D8,C3,C4,C5,C6,C7,C8,C9,S10,H10`으로 잠근다.
- 런 중 어떤 카드군으로도 전환 가능하다.
- 끝까지 네임드 카드를 받지 않는 온리 순수덱 클리어도 가능하게 한다.
- 순수덱 지원은 새 전용 카드군보다 유물/패시브/이벤트 등 카드 외부 시스템을 우선 검토한다.
- PURE의 장점은 직접 전투 보너스보다 카드 선택/교체/제거 자유도 쪽에 둔다.

후보 특전은 카드 보상 선택지 +1, 네임드 교체 비용 감소, 제거/슬롯 조정 비용 감소 등이 있으나 아직 확정하지 않는다.

## 4. 순수카드 → 네임드화 성장

로그라이크의 주요 차별점으로 **같은 랭크+무늬 슬롯의 순수카드를 네임드 변형으로 교체/진화**시키는 방식을 우선 검토한다.

예:

`7♠ 순수 카드 → 7♠ 검은 탄환`

또는 동일 7♠ 슬롯의 다른 테마 변형으로 교체한다.

원칙:

- 숫자와 무늬는 보존한다.
- 세트/런 분포를 무너뜨리지 않고 효과 정체성을 성장시킨다.
- 모든 순수카드를 네임드화하는 것이 자동 정답이 되어서는 안 된다.
- 성장 방식은 `교체 / 추가 / 제거` 세 축을 검토한다.
- 교체는 기본 성장 수단, 추가/제거는 더 희소한 수단으로 두는 방향이 유력하다.

## 5. 카드 보상 구조

일반 전투 보상 후보는 기본적으로 **3장 중 1장 선택 + 건너뛰기**를 우선 검토한다.

세 슬롯의 역할을 다르게 두는 안:

1. 현재 빌드 강화 — 현재 덱의 행동과 직접 시너지
2. 확장/새 방향 — 새로운 테마 또는 혼합 빌드의 초동
3. 기반 보강 — 범용 네임드, 순수 슬롯 개선, 숫자/무늬 보정

보상은 `V-SIGNAL 카드가 많다` 같은 단순 테마명 검사만 보기보다 실제 덱 행동 태그를 함께 본다.

예시 행동 태그:

- 새 세트 생성
- 런 생성/확장
- 상대 조합 붙이기
- 회수
- 정비
- 버림패 이용
- 스위치 반환
- 러미
- 상태 부여/해제

따라서 회수 중심 덱에는 V-SIGNAL뿐 아니라 MAIL-ROUTE, POINT-BLANK, SCRAP-SHIFT 등 관련 카드가 새 방향 후보로 나타날 수 있다.

## 6. 새 테마 진입과 보상 단계

새 카드군을 처음 발견했을 때 피니셔만 덜렁 등장하는 문제를 막기 위해 테마 내부 역할 단계를 둔다.

`초동 → 엔진 → 보상 → 피니셔`

- 처음 진입 시 초동/기본 엔진의 출현 가중치를 높인다.
- 실제 덱에 전용 개념 생성 수단이 생기면 중급 엔진을 연다.
- 엔진이 갖춰진 뒤 강한 보상/피니셔가 자연스럽게 등장하도록 한다.
- 별도 `테마 레벨` 자원을 만드는 대신 현재 덱에 실제로 어떤 기능이 있는지 검사하는 방식을 우선한다.

전투 등급별 보상 방향 후보:

- 일반전: 초동 / 기본 엔진 / 범용 / 기반 개선
- 엘리트: 강한 엔진 / 규칙 변형 / 희귀 유물
- 보스: 피니셔 / 시그니처 / 대규모 카드 개조

## 7. 지역 기반 카드풀

`테마군 하나 = 지역 하나`로 고정하지 않는다.

대신 **지역 = 공통 문화/환경 + 서로 어울리는 여러 테마군 + 지역 공용 카드** 구조를 우선 검토한다.

새 카드군을 만들 때도 먼저 지역의 문화, 직업, 갈등, 인프라를 만들고 거기서 여러 집단/테마군이 파생되게 하는 방향이 유력하다.

카드 계층 후보:

`전역 범용 → 지역 공용 → 테마군 → 캐릭터 고유`

지역 공용 카드는 같은 지역의 서로 다른 테마군이 공유하는 행동 축을 지원한다.

## 8. 공통 시작 구역

런 초반은 특정 테마 지역으로 바로 들어가기보다 **공통 구역에서 빌드의 씨앗을 찾는 구조**를 우선한다.

공통 구역 후보 보상:

- 순수카드/슬롯 개선
- 범용 네임드
- 여러 테마의 초동 카드
- 상점
- 이벤트
- 기본 유물

이후 플레이어가 현재 덱의 방향을 보고 지역을 선택한다.

즉 `지역이 빌드를 정한다`보다 **카드가 씨앗을 주고 지역이 그 방향을 밀어준다**는 순서를 우선한다.

## 9. 지역 후보

### NEON//ARC — 네온아크

미디어, 가상 방송, SNS, 광고, 배송, 정보망이 밀집한 초고밀도 상업도시.

현재 연계 테마 후보:

- `V-SIGNAL`
- `MAIL-ROUTE`

향후 해커, 기자, 광고, 데이터 브로커 계열 등을 추가할 수 있다.

주요 행동 성향 후보: 정비 / 회수 / 카드 이동 / 패순환 / 정보 전달.

### RED//ZONE — 레드존

도시전, 용병, 정찰, 돌입전이 이어지는 분쟁구역.

현재 연계 테마:

- `ZERO-SIGHT`
- `POINT-BLANK`

향후 폭파병, 의무병, 용병, 드론 정찰 계열 등을 추가할 수 있다.

주요 행동 성향 후보: 상대 조합 붙이기 / 표적 / 접전 / 고정 / 봉인 / 스위치 압박.

### IRON//GRAVE — 아이언그레이브

폐공장, 고철 산, 버려진 기계와 로봇이 쌓인 산업폐허.

현재 연계 테마 후보:

- `SCRAP-SHIFT`

향후 로봇, 공장, 중장비, 기계공 테마 등을 추가할 수 있다.

주요 행동 성향 후보: 회수 / 소모 / 이동 / 부품화 / 재조립.

### OLD//QUARTER — 올드쿼터

낡은 골목, 사설 탐정, 범죄조직, 암시장, 오래된 상점과 계약이 얽힌 구시가지.

향후 후보:

- 탐정
- 마피아/조직
- 도둑
- 밀수
- 계약/거래

주요 행동 성향 후보: 버림패 / 정보 / 거래 / 방해 / 상대 행동 추적.

### NULL//WARD — 널워드

기록과 지도에서 삭제된 격리구역. 실험실, 이상현상, 변이체와 버려진 시설이 남아 있다.

향후 후보:

- 실험체
- 초능력
- 괴이
- 저주
- 변이

주요 행동 성향 후보: 카드 변형 / 상태 / 위험한 규칙 예외 / 고위험 고보상.

현재 프로토타입에서는 두 지역 뒤 진입하는 후반 특수구역으로 사용한다(25절). 최종 배치·세부 콘텐츠·난도는 플레이테스트 이후 확정한다.

## 10. 지역 보상은 확률 가중 방식

한 지역에 들어갔다고 해당 테마만 등장하지 않는다.

예를 들어 네온아크에서는 V-SIGNAL과 MAIL-ROUTE 및 네온아크 공용 카드의 비중이 높아지지만, 범용 카드와 소량의 타지역 카드도 등장할 수 있다.

지역 선택의 의미는 `이 테마를 강제로 한다`가 아니라 **이런 플레이스타일이 잘 나오는 환경으로 간다**에 둔다.

정확한 비율은 미정이다.

## 11. 현재 테마군과 지역 관계

- `V-SIGNAL` — 네온아크 중심 후보. 방송/합방/RAID/회수/러미.
- `MAIL-ROUTE` — 네온아크 중심 후보. 우편 지정/목적지/도착/반송/재배송.
- `ZERO-SIGHT` — 레드존 중심. 표적/관측/정밀 타격.
- `POINT-BLANK` — 레드존 중심. 접전/침투/회수/교대.
- `SCRAP-SHIFT` — 아이언그레이브 중심 후보. 부품/해체/재조립.

기존 테마의 상세 카드 효과는 별도 테마 문서에서 관리한다. 이 문서는 지역/로그라이크에서의 위치를 기록한다.

## 12. 혼합 빌드의 목표 경험

예시 A:

`PURE → 공통 구역에서 ZERO-SIGHT 초동 → 레드존 → 표적/접전 혼합 → 네온아크 → MAIL-ROUTE 획득 → 표적 조합을 목적지로 사용`

예시 B:

`V-SIGNAL 성향 캐릭터 → 네온아크 → RAID/회수 중심 → 아이언그레이브 → SCRAP-SHIFT 획득 → 방송 카드를 부품화하는 혼합덱`

스타터는 목적지가 아니라 출발점이어야 한다.

## 11. 런 초기화 구조 프로토타입

일반 1대1 전투의 `캐릭터 경향 + 테마 + 30장 덱빌더`와 로그라이크 시작 선택을 분리한다. 로그라이크 스타터는 `유랑자 / 수집가 / 회수꾼 / 광대 / PURE` 다섯 출발점을 별도 UI에서 고르며, 캐릭터 선택은 **보상·행동 방향의 힌트**이지 특정 테마 카드군 잠금이 아니다.

현재 `rummyDuelRoguelikeRunDraftV1` 초안 구조는 다음 원칙만 확정한다.

- 모든 런은 `common-start` 공통 시작 구역에서 출발한다.
- `themeLocks`는 항상 빈 배열이며 타 테마 카드 보상을 허용한다.
- 지역 경로와 노드 위치는 빈 경로/0에서 시작한다.
- 카드 슬롯 정체성은 기존 `base rank + suit`를 유지한다.
- 모든 스타터는 30장이다. 일반 4스타터는 순수 23 + 네임드 정규 6 + 네임드 조커 1이며, PURE는 순수 정규 29 + 기본 와일드 조커 1로 네임드 0장을 유지한다.
- 일반 4스타터의 실제 네임드 ID는 `ROGUELIKE_STARTER_LOADOUTS`로 고정하고 `deckPlan.cardBlueprints`에 30장 조립 청사진을 저장한다.
- 직접 전투 패시브는 v1에서 전원 `none`이다. 캐릭터 `weights`는 `character-tendency-score-v1` 보상 후보 랭킹에만 쓰며 실제 보상 등장 확률은 계속 `unresolved`로 둔다.
- `prepared` 런 덱은 별도 버튼으로 실험전에 전달할 수 있고 테스트 보상 노드를 수동 발급할 수 있다. 이 초기 구조 이후 자동 전투 보상은 20–25절, `completed` 런 상태는 25절에서 추가했다.

## 12. 행동 태그 기반 카드 보상 후보 알고리즘 v1

`action-tags-v1`은 실제 보상 확률표가 아니라 **후보 랭킹 계층**이다. 기존 일반전 캐릭터 가중치를 그대로 드롭 확률로 재사용하지 않고, 네임드 효과 태그를 플레이어가 이해할 수 있는 행동 태그(`세트 / 런 / 붙이기 / 회수 / 정비 / 러미 / 버림패 / 스위치 / 상태 / 상대 조합 / 규칙 변형`)로 정규화한 뒤 현재 런 덱과 비교한다.

기본 3역할은 다음과 같다.

1. `현재 강화` — 현재 덱에서 이미 반복되는 행동과 겹치는 카드에 높은 점수를 준다. 스타터 성향은 작은 tie/방향 보정일 뿐 확률 잠금이 아니다.
2. `새 방향` — 현재 덱에 없는 행동과 새 테마를 우선한다. 새 테마에 이미 초동 메타가 정의되어 있으면 초동을 먼저 올리고, 초동 없이 피니셔만 제시하는 후보는 낮춘다. 현재 라이브 기준 ZERO-SIGHT는 `관측수 / 스코프 조정`이 `ONE SHOT`보다 첫 진입 우선이다.
3. `기반 보강` — 테마 의존도가 낮은 범용 카드와 정비/회수/버림패 같은 순환 기반 행동을 우선한다.

현재 v1의 후보 풀은 **덱에 이미 존재하는 원본 rank+suit 슬롯의 네임드 교체**로 제한한다. 현재 장착 중인 동일 변형, 조커, 덱에 없는 슬롯은 제외한다. 이는 `교체`를 기본 성장축으로 둔 기존 원칙을 따른 것이며 `추가 / 제거` 보상의 경제가 확정되기 전까지 서로 섞지 않기 위함이다.

세 역할은 가능한 경우 서로 다른 카드를 뽑고 `건너뛰기`는 항상 별도 선택지로 유지한다. 같은 입력과 seed에서는 결과가 결정적이라 회귀/밸런스 비교가 가능하다. 캐릭터/테마 하드 잠금은 만들지 않으므로 새 방향 역할에서 다른 테마 카드가 정상적으로 등장할 수 있다.

현재 진행도 화면에서는 테스트 보상 노드 발급 시 저장된 `runDeck`의 현재 슬롯/변형과 현재 해금 풀로 후보를 한 번 계산한다. 노드에 저장된 후보는 새로고침이나 해금 변화로 재계산하지 않으며, 그중 1장을 확인해 런 덱에 적용하거나 노드 전체를 건너뛴다. 일반 전투와 해금 진행도는 변경하지 않는다. 상세한 발급/수령 계약은 19절을 따른다.

아직 확정하지 않는 것:

- 일반전 / 엘리트 / 보스별 희귀도와 보상 등급
- 실제 드롭 확률과 역할별 등장 확률
- 카드 추가/제거의 경제 비용
- 스타터별 정확한 보상 가중치 수치
- 지역 가중치와 타지역 출현률

## 13. 동일 슬롯 교체 UI 계약 v1

카드 보상, 상점, 이벤트에서 네임드를 얻는 기본 성장 행동은 서로 다른 덱 수정 코드를 만들지 않고 `replace-slot-variant` 공용 계획을 사용한다.

계획이 반드시 보여 주는 정보:

- 출처: `reward / shop / event`
- 원본 `rank+suit` 슬롯
- 현재 상태: 순수 카드 또는 현재 네임드 변형
- 교체 후 네임드 변형
- `preservesSlot: true`
- `changesDeckSize: false`
- 취소 가능

잘못된 후보는 계획 자체를 만들지 않는다. 조커, 현재 덱에 없는 슬롯, 이미 장착한 동일 변형은 동일 슬롯 교체 대상이 아니다.

현재 UI 프로토타입에서는 후보 선택 후 `현재 → 교체 후`를 확인하고 런 덱에 적용하거나 선택을 취소할 수 있다. 적용 직전 runId·노드 ID·미처리 상태·덱 revision/지문·현재 변형·발급 당시 고정 후보를 재검증한다. 선택 취소는 노드를 소모하지 않고, 수령 또는 별도 건너뛰기는 해당 노드를 완료한다. 상점/이벤트의 결제·조건 처리는 아직 구현하지 않아 해당 출처의 실제 적용은 허용하지 않는다.


## 14. 성장 경제 구조 실험 v1 — 제거 vs 동일 슬롯 교체

실전 상점 가격이나 드롭 등급을 정하기 전에, `experiments/m11a-growth-economy.mjs`로 **덱 구조 자체의 가치만 분리**해 측정했다. 실험은 현재 `index.html`의 실제 세트/런 판정을 직접 읽으며, 현재 기본 30장 구조인 `일반 rank+suit 슬롯 29장 + 조커 1장`에서 결정적 4,000 seed의 6장 손패를 비교한다. 조커 제거는 별도 경제축으로 보고 이번 제거 스윕에서 제외한다.

기준 결과:

- 기본 30장: 조합 가능 손패 32.48%, 세트 포함 20.03%, 런 포함 21.88%, 서로 겹치지 않는 2조합 잠재력 0.68%, 손패당 평균 합법 3장 조합 0.551.
- 동일 슬롯 네임드 교체: 덱 크기와 원본 rank+suit 슬롯이 같으므로 위 구조 지표 변화량은 정확히 0. 경제 가치는 구조가 아니라 **네임드 효과와 희소도**에서 나온다.
- 일반 슬롯 1장 제거 평균: 조합 가능률 32.73%로 +0.25%p, 평균 합법 조합 0.563으로 +0.012였지만 2조합 잠재력은 0.55%로 -0.13%p였다.
- 제거 효과는 슬롯별로 크게 달랐다. H10 제거는 조합 가능률 34.73%(+2.25%p), S7 제거는 30.10%(-2.38%p)였다. 즉 주변 슬롯 제거는 남은 구조를 농축할 수 있지만, 중앙 RUN 축 제거는 오히려 덱의 조합성을 무너뜨릴 수 있다.

### M11A 경제 결정

- **제거를 동일 슬롯 교체의 단순 상위 업그레이드로 가격 책정하지 않는다.**
- 동일 슬롯 교체는 기본 성장축으로 유지한다. 덱 구조를 보존하므로 보상 후보 알고리즘과 현재 `replace-slot-variant` 계약에 그대로 맞는다.
- 제거는 `reward` 교체 후보 풀과 섞지 않고 **별도의 희소 성장 행동**으로 둔다. 상점/이벤트 등 명시적인 출처에서 제공하는 방향을 우선한다.
- 제거 확정 UI에는 현재 덱빌더의 숫자/무늬/세트/런 분석을 재사용해 제거 전후 구조 변화를 보여 주고, 핵심 RUN 축 또는 다중 조합 잠재력이 감소하면 경고한다.
- 조커 제거는 일반 슬롯 제거와 같은 가격표를 쓰지 않고 별도 설계 대상으로 남긴다.
- 정확한 골드 비용, 등장 확률, 일반/엘리트/보스별 보상 등급은 이 구조 실험만으로 잠그지 않는다. M12 실전 전투 데이터와 실제 런 경제가 생긴 뒤 확정한다.

이 결정은 ROADMAP의 `카드 제거와 네임드 교체의 경제적 가치 비교`를 닫지만, `보상 희귀도/전투 등급`과 실제 가격 수치는 계속 미확정으로 남긴다.

## 15. 스타터 수치 기준 v1 — 30장 / PURE 기준 구조

M11A 런 초안의 `deckPlan`을 미확정 자리표시자에서 실제 수치 계약으로 승격한다. 아래 기준은 현재 런 덱 조립과 별도 실험 전투의 Source of Truth다.

### 공통 30장 골격

- 모든 스타터는 **30장**으로 시작한다.
- 정규 카드 슬롯은 **29개**, 조커 슬롯은 **1개**다.
- 정규 29슬롯은 `CORE_IDS.slice(0,29)`를 공통 기준으로 사용한다: `S3,S4,S5,S6,S7,S8,S9,H2,H3,H4,H7,H8,H9,D2,D3,D4,D5,D6,D7,D8,C3,C4,C5,C6,C7,C8,C9,S10,H10`.
- 네임드 정규 카드는 이 29개 원본 rank+suit 슬롯을 **교체**할 뿐 슬롯을 추가하지 않는다. 따라서 스타터마다 SET/RUN 기본 기하를 다르게 주지 않고 카드 효과/보상 성향으로 정체성을 만든다.

### 유랑자 / 수집가 / 회수꾼 / 광대

- 순수 카드: **23장**.
- 네임드 정규: **6장**.
- 네임드 조커: **1장**.
- 총 네임드/효과카드: **7장 = 23.3%**, 순수카드: **23장 = 76.7%**.
- 6개의 네임드 정규는 서로 다른 원본 슬롯을 사용한다. 시작부터 하나의 테마 완성 콤보를 고정 지급하지 않는다.
- 유랑자: `H2 / C5 / S10 / D2 / C6 / H10 + J1`.
- 수집가: `S9 / H7 / H8 / H9 / D7B(D7) / D8 + J3`.
- 회수꾼: `S3 / S4 / D3 / D7 / C7 / H3 + J4`.
- 광대: `C8 / D6 / D5 / D4 / C4 / C3 + J5`.
- 네 스타터는 정확한 네임드 ID를 서로 공유하지 않으며 테마 전용 카드를 시작 덱에 넣지 않는다. 성향은 범용 카드의 행동 태그로만 제시한다.

### PURE

- 순수 정규: **29장**.
- 기본 와일드 조커: **1장**.
- 네임드/고유 효과카드: **0장**.
- 기본 와일드 조커는 `suit === 'J'`가 제공하는 조합용 와일드 판정만 가진다. `광대왕 조커(J1)`의 고유 효과인 조합 정리 후 즉시 원주인 덱 아래 복귀를 포함해 어떤 네임드 효과도 갖지 않는다. 일반 카드처럼 소모/재순환 흐름을 따른다.
- 이 때문에 PURE도 다른 스타터와 같은 30장/조커 1장 구조를 유지하면서 `효과카드 0장` 정의를 지킨다. 초기 6장 손패의 순수한 SET/RUN 구조 비교에서는 기존 M11A 30장 기준 골격을 그대로 사용할 수 있다.

### 캐릭터 가중치 / 패시브

- 유랑자: `combo 1.7 / cycle 0.9 / extend 0.6 / pressure 0.3`.
- 수집가: `hold 1.8 / sustain 0.8 / pressure 0.4 / status 0.3`.
- 회수꾼: `discard 2.0 / cycle 1.1 / interact 0.7 / control 0.4`.
- 광대: `trick 2.2 / combo 1.0 / interact 0.6 / status 0.4`.
- PURE: 가중치 없음.
- 이 값들은 **보상 후보 랭킹 점수**에만 사용하는 `character-tendency-score-v1`이다. 실제 드롭 확률표가 아니며 0가중치 테마/행동도 후보에서 제외하지 않는다.
- 스타터 직접 전투 패시브는 v1에서 전원 `none`이다. M12 실전 데이터 전에 카드 수치 + 캐릭터 전투 패시브 + 보상 확률을 동시에 조정하는 다중 밸런스 축을 만들지 않는다. 향후 유물/패시브 시스템을 추가하더라도 이 결정과 별도 단계에서 검증한다.

## 16. 실제 스타터 네임드 조립 v1

`ROGUELIKE_STARTER_LOADOUTS`는 일반 4스타터의 네임드 정규 6장과 네임드 조커 1장을 실제 카드 ID로 고정한다. `roguelikeStarterDeckPlan()`은 이 프리셋을 공통 29슬롯에 덮어써 `variantBySlot`, `namedRegularIds`, `jokerVariantId`, 30개의 `cardBlueprints`를 만든다. 일반 전투 `makeDeck()`과는 분리하며, v4에서 도입한 `runDeck`이 이 청사진을 복제해 현재 덱 상태로 보존한다. 현재 저장 형식은 보상 노드 이력을 추가한 v5다.

선정 원칙:

- 테마 전용 `themeId` 카드는 스타터에서 제외한다. 캐릭터 선택이 특정 지역/테마의 완성 초동을 공짜로 지급하지 않게 한다.
- 네 캐릭터 사이에서 정확한 시작 네임드 ID를 공유하지 않는다. 첫 런부터 캐릭터 인상이 겹치는 것을 줄인다.
- 정규 네임드는 모두 공통 29슬롯 안에 있고 캐릭터당 원본 슬롯 중복이 없다. 따라서 30장 SET/RUN 구조는 모든 스타터에서 동일하다.
- 현재 `CHARACTERS.weights × TENDENCY_BY_TAG` 단순 성향 합계로 각 7장 프리셋을 평가했을 때 자기 캐릭터 점수가 다른 캐릭터보다 가장 높아야 한다. 이는 승률 보정이 아니라 **출발 행동 정체성 검증**이다.
- 실제 카드 파워와 승률은 M12 실전 표본으로 다시 본다. 성향 점수만으로 강약 밸런스를 확정하지 않는다.


## 17. 런 덱 저장과 보상 적용 v1

- 런 초안 v4에서 시작 청사진 `deckPlan`과 변경 가능한 `runDeck`을 분리했다. 현재 v5도 이 계약을 유지한다. 현재 덱은 카드 30장의 원본 슬롯·변형 ID·순수/기본 와일드 여부와 revision을 저장한다.
- v1~v3 초안은 스타터 청사진으로 최초 덱을 생성한다. v4 이상 로드는 교체를 보존하며 중복 슬롯, 잘못된 변형, 조커 혼입, 잘못된 장수는 거부한다. 손상된 저장 덱을 스타터로 조용히 되돌리지 않는다.
- v4의 반복 교체 미리보기는 v5부터 노드별 발급/1회 처리로 대체했다. 테스트 노드를 발급할 때 현재 런 덱과 해금 풀로 후보를 고정하며, 한 노드를 수령/건너뛰기한 뒤에만 다음 테스트 노드를 발급할 수 있다.
- 동일 슬롯 교체는 저장 성공 때만 완료로 표시한다. 중복 적용, 삭제/새 런의 오래된 선택, 저장 실패는 변경 없이 거부한다.
- 일반 대전 덱, 클리어/레벨 진행도, 전투 상태는 변경하지 않는다. 별도 실험 전투에서는 이 런 덱을 독립 복제하며 전투 카드의 임시 상태는 런 저장 덱으로 역류하지 않는다(18절).

## 18. 런 덱 실험 전투 v1

- 진행도 화면에서 저장된 런 덱이 있을 때만 `런 덱 실험전 시작`을 활성화한다. 삭제되거나 손상된 런 덱으로는 시작하지 않는다.

## 19. 보상 노드 발급과 1회 처리 v1

보상 후보를 누를 때마다 자유롭게 교체하던 v4 개발 미리보기를 **발급 → 선택 확인 → 1장 수령 또는 건너뛰기**의 저장 가능한 노드 계약으로 바꾼다. 현재 단계의 노드는 `source: prototype`인 수동 테스트 노드다. 실제 맵/전투 완료 자격을 대신하지 않으며, 실험전 승리나 다시 하기로 자동 지급하지 않는다.

### 저장 및 마이그레이션

- 런 초안 v5는 기존 `runDeck`과 같은 `rummyDuelRoguelikeRunDraftV1` 키에 `rewardNodes: {version: 1, baseRevision, entries}`를 함께 저장한다.
- 노드 ID는 `runId:reward:sequence`로 런과 발급 순서를 고정한다. 노드에는 `pending / claimed / skipped`, 발급 시 덱 revision/슬롯 지문, 알고리즘 ID, 후보의 카드 ID·역할·원본 슬롯·교체 전 변형, 수령한 카드 ID를 저장한다.
- 노드 sequence는 테스트 보상 이력의 순서다. 실제 맵의 `nodeIndex`나 지역 경로를 진행시키지 않는다.
- v1~v3은 기존처럼 스타터 덱을 생성한다. v4는 기존 교체 카드·runId·생성 시각·revision을 보존하고 그 revision을 빈 보상 이력의 `baseRevision`으로 삼는다. 과거 미리보기 교체를 새 노드 수령으로 꾸미거나 스타터로 초기화하지 않는다.
- v5에서 누락/손상된 보상 이력은 빈 이력으로 복구하지 않고 로드를 거부한다. 노드 순서·후보 역할/중복·슬롯 정합성·완료 결과와 revision을 검사하고, 수령 이력을 역순으로 되짚어 각 발급 당시 덱 지문과 교체 전 변형을 대조한다.

### 발급·수령·건너뛰기

- 발급 요청은 런 ID·sequence·덱 revision/지문에 묶인다. 같은 요청을 다시 호출하면 이미 저장된 노드를 그대로 반환하고, 완료한 노드를 다시 열지 않는다. 대기 중인 노드가 있으면 다음 노드를 발급하지 않는다.
- 후보 생성은 발급 시 한 번만 한다. `현재 강화 / 새 방향 / 기반 보강` 역할별 최대 1장, 총 3장의 서로 다른 카드 ID를 저장한다. 현재 네임드와 동일한 변형, 조커, 덱 외 슬롯은 제외한다. 풀에 0~2장만 있으면 가능한 수만 제시하고 중복으로 채우지 않는다.
- 새로고침, 화면 재진입, 일반 해금 상태 변화는 이미 발급한 후보를 재추첨하거나 박탈하지 않는다. 같은 카드가 다른 노드에도 나올 수 있지만 각 노드 안의 후보는 고정이다.
- 선택 확인은 저장을 바꾸지 않는다. 수령은 미처리 노드의 고정 후보인지와 교체 전 슬롯/변형을 재검증한 뒤, 해당 슬롯 교체·덱 revision 증가·`claimed`/수령 카드 기록을 **같은 키에 한 번 저장**한다.
- 건너뛰기는 `skipped`만 저장하고 카드·덱 revision은 바꾸지 않는다. 선택 취소는 아무것도 소모하지 않는다. 수령/건너뛰기는 **런 전체가 아니라 각 노드당 한 번**이며 완료한 노드에서는 남은 후보도 받을 수 없다.
- 저장 실패는 완료로 표시하지 않는다. 기존 덱과 대기 노드를 유지해 재시도할 수 있게 한다. 오래된 후보·적용·건너뛰기·발급 버튼은 다른 노드나 새 런에 보상을 적용할 수 없다.

### 프로토타입 UI와 후속 범위

- `캐릭터·해금 → 로그라이크 런 스타터 → 테스트 보상 노드 발급`에서 실험한다. 발급된 후보는 재진입 시 자동 복원되고, `1장 수령 · 런 덱에 적용` 또는 `이번 노드 건너뛰기`로 완료한다.
- 발급/수령/건너뜀 누적 수와 최근 5개 처리 결과를 표시하되 저장 이력은 전부 보존한다. 현재 노드를 완료하면 다음 테스트 노드 버튼을 활성화한다.
- 일반 대전 덱·클리어·레벨·해금·M12 표본 및 진행 중인 전투 카드 복제본은 바꾸지 않는다. 다음 런 덱 실험전은 변경된 저장 덱을 새로 복제한다.
- 실제 맵/전투 노드 완료에 따른 보상 발급, 체력/지도 지속, 상점·이벤트 결제/조건, 일반/엘리트/보스 희귀도와 유물은 후속 작업이다.
- `tests/m11a-reward-nodes.mjs`는 마이그레이션, 후보 고정, 재발급, 노드당 1회 수령/건너뛰기, 동일 슬롯 연속 교체, 빈 풀, 손상 저장, 저장 실패, 오래된 UI 콜백과 일반전/전투 격리를 검증한다.

## 22. 지역 실전 보상 성향 v1 — 후보 랭킹 프로토타입

2026-09-02 구현. 검증된 지역 전투의 승리 보상에서만 기존 행동 태그 랭킹에 지역 가산점을 더한다. 공통 시작 3연전과 수동 테스트 보상은 기존 결과를 유지한다. 지역 선택 화면에 보상 성향과 실제 후보 조건을 표시한다.

| 지역 | 공용 행동 가산점 | 라이브 테마 가산점 |
| --- | --- | --- |
| 네온아크 | 정비 +2, 러미 +1, 회수 +1 | V-SIGNAL +2 |
| 레드존 | 상대 조합 +2, 붙이기 +1, 스위치 +2, 상태 +1 | ZERO-SIGHT / POINT-BLANK +2 |
| 아이언그레이브 | 회수 +3, 붙이기 +1 | 없음 |
| 올드쿼터 | 버림패 +3, 상대 조합 +1, 상태 +1 | 없음 |

- `현재 강화 / 새 방향`은 행동과 테마 가산점을 합쳐 최대 +6점만 받는다. 기존 덱 시너지, 캐릭터 경향, 새 테마 초동 판정을 먼저 계산하며 큰 기존 시너지를 무조건 뒤집지 않는다.
- `기반 보강` 점수에는 가산하지 않는다. 앞의 두 후보를 제외한 남은 풀에서 기존 범용/순환 기준으로 고르므로 기반 보강의 최종 카드까지 항상 같다는 뜻은 아니다.
- 기존 `entryStatus: payoff` 판정인 새 테마 후속 카드는 지역 가산점을 받지 않는다. 후보에서는 제거하지 않는다. 기존 테마 판정은 실제 덱에 해당 테마가 있는지를 기준으로 하며 모든 개별 콤보의 실행 가능성을 보장하지 않는다.
- MAIL-ROUTE와 SCRAP-SHIFT처럼 아직 라이브 카드가 없는 테마는 후보나 테마 가산점에 새로 추가하지 않는다. 아이언그레이브와 올드쿼터는 공용 행동으로 차이를 만든다.
- 해금된 라이브 카드, 보유한 원본 슬롯, 현재와 다른 변형, 조커 제외라는 자격은 그대로다. 관련 카드가 없어도 범용/다른 지역 카드를 고를 수 있으며 후보가 부족하면 있는 만큼만 표시하고 건너뛰기를 허용한다.
- 특히 현재 고정 29슬롯에는 ZERO-SIGHT 초동 CA/C2가 없다. 지역 선택으로 덱 밖 카드가 생기거나 특정 테마의 초동을 보장하지 않는다. 신규 슬롯 진입은 별도 설계 과제다.
- 새 지역 보상에는 `algorithm: action-tags-region-v1`과 `regionId`를 저장한다. 저장 v6는 기존 `action-tags-v1` 영수증도 그대로 읽으며 과거 지역 보상도 재추첨하거나 새 가중치 적용으로 표시하지 않는다. 지역 ID는 실제 battle 노드의 지역과 일치해야 한다. 수동 테스트/공통 시작에 지역 알고리즘을 붙인 저장은 거부한다.
- 후보는 승리 시 한 번만 고정한다. 불러오기, 미리보기, 중복 승리, 수령/건너뛰기에서 현재 랭킹이나 해금 목록으로 다시 고르지 않는다. 덱 교체와 1회 처리 결과는 계속 함께 저장한다.
- 검증: `tests/m11a-region-rewards.mjs`. 5스타터 × 4지역 × 64개 동일 입력 시드, 총 1,280쌍에서 902쌍의 후보 구성이 달라졌고 네 지역 모두 차이를 냈다. 후보 풀 크기·슬롯 자격·중복 방지·결정론·가산점 상한·빈/소수/타지역 풀·구버전 고정 후보·저장 실패·잘못된 지역 정보를 함께 검증했다. 시드는 동점 해소용이며 이 비교는 드롭 확률이나 전투 밸런스의 통계 검증이 아니다.

지역별 적/보스 프로토타입은 아래 23절로 이어진다. 실제 보상 확률·희귀도·지역 카드 비율은 아직 확정하지 않았다.

## 23. 지역별 적과 중간 보스 v1

2026-09-02 구현. `공통 시작 3전투 → 지역 선택 → 지역 일반 교전 3회 → 중간 보스 1회`로 연결한다. 공통 시작과 RUN TEST의 상대 생성은 유지하며 지역 실전에서만 전용 구성을 사용한다.

| 지역 | 일반 상대 1 / 2 / 3 | 중간 보스 | 일반 필드 → 보스 필드 |
| --- | --- | --- | --- |
| 네온아크 | 송출 안내원 / 회선 중계원 / 합방 조율사 | 앙코르 디렉터 | 파산한 카지노 → 축제 거리 |
| 레드존 | 전방 관측병 / 돌입 사수 / 표적 추적자 | 교전 지휘관 | 무법지대 → 환승 터미널 |
| 아이언그레이브 | 부품 수거원 / 폐기물 정비사 / 재조립 기사 | 고철 감독관 | 회전교차로 → 공사장 |
| 올드쿼터 | 골목 중개인 / 암시장 감정인 / 계약 추심원 | 암시장 집행관 | 암시장 → 전당포 |

- 모든 적 덱은 원본 슬롯이 중복되지 않는 정규 카드 29장과 네임드 조커 1장이다. 정규 네임드는 일반 1/2/3전에서 6/8/10장, 보스에서 12장이며 나머지는 순수 카드다. 코어는 양쪽 모두 3×60이고 시작 손패 8장, 스위치/회수 제한/공용 AI 규칙도 유지한다. 별도 보스 패시브나 추가 체력/행동은 부여하지 않는다.
- 실제 구성은 `ROGUELIKE_ENCOUNTER_PROFILES`에 고정한다. 네온아크는 V-SIGNAL·패순환, 레드존은 ZERO-SIGHT·POINT-BLANK·상대 조합, 아이언그레이브는 회수·재활용·보호, 올드쿼터는 버림패·거래·간섭을 사용한다. 아직 없는 테마나 효과를 새 카드인 것처럼 생성하지 않는다.
- 적 슬롯은 지역별로 별도 구성한다. 레드존에는 CA/C2 초동을 넣고 중간 보스에는 ZSD6/ZSSK와 함께 사용하게 한다. 네온아크에는 H5와 CK를 넣어 라이브 V-SIGNAL 카드를 쓸 수 있게 한다. 적 구성은 플레이어의 해금/고정 29슬롯을 우회하는 덱 보상이 아니며 플레이어 저장 덱을 변경하지 않는다.
- 지역과 노드에 따른 적 구성·필드는 재도전에도 동일하다. 덱 셔플과 실제 행동은 매 전투 달라질 수 있다. 필드는 양쪽에 적용하는 기존 공용 필드이며, 해당 필드의 일반전 해금 여부와 별개로 지역 전투에서 사용한다.
- 전투 시작 전에 상대 이름·전술·총 카드/네임드 수·필드 전체 효과를 진행 화면에 표시한다. 전투 중 안내에도 상대와 필드를 표시하고 중간 보스 승패를 결과창에 구분한다.
- 보스는 `${regionId}-boss`라는 별도 battle 노드로 저장한다. 기존 일반 3전투 영수증을 보스 처치로 바꾸지 않는다. 지역 3전투까지 완료한 v6 저장은 보스 전투 자격을 받으며, 마지막 일반 보상이 남아 있으면 먼저 처리해야 한다.
- 보스도 지역 성향이 반영된 고정 후보 3장 중 1장/건너뛰기 보상을 한 번 발급한다. 별도 희귀도·유물·추가 보상 수량은 아직 확정하지 않았다. 보스 승리 보상까지 처리하면 이번 구역 완료로 표시한다. 첫 지역 뒤 다음 지역 선택은 아래 24절에서 연결했다. 이는 최종 런 클리어가 아니며 일반 클리어/레벨/해금/M12에는 반영하지 않는다.
- 패배/무승부는 같은 보스에 재도전할 수 있다. 저장 실패와 오래된 전투 자격은 진행하지 않고, 같은 승리 결과를 다시 처리해도 영수증·보상이 늘어나지 않는다.
- 검증: `tests/m11a-region-encounters.mjs`에서 16종의 실제 전투 카드 생성·초기 손패·30슬롯·기본 체력·필드·사전 안내·승패/무승부/저장 실패·중복 결과·기존 6승 복원과 잘못된 덱을 확인한다. 16종 × 32손패에서 공용 AI의 새 조합 선택을 검사했다. 전체 120개 회귀가 통과했으며, 512개 조합 선택 검사는 전체 전투 승률이나 보스 난도 검증을 대신하지 않는다.

추가 지역 선택은 아래 24절, 후반 특수구역·최종 보스·런 완료는 25절로 이어진다. 상점·이벤트·엘리트 및 적 난도·보스 보상 경제 확정은 계속 미완료로 둔다.


## 24. 두 번째 지역과 경로 이력 v1 — 저장 v7

2026-09-02 구현. `공통 시작 3전투 → 첫 지역 선택 → 일반 3전투 + 보스 → 미방문 지역 선택 → 일반 3전투 + 보스`까지 연결한다. 첫 지역은 네 곳, 두 번째 지역은 이미 간 곳을 제외한 세 곳 중 선택하므로 가능한 방문 순서는 12개다.

- `ROGUELIKE_ROUTE_LIMITS.regionVisits: 2`는 분기 지역 두 곳을 선택하는 프로토타입 범위다. 이 단계의 전투는 총 11개였으며, 아래 25절에서 널워드 3전투와 런 완료를 추가했다. 최종 지역 수·런 길이·후반 난도를 확정하는 수치는 아니다.
- 저장 v7의 `regionPath`는 중복 없는 0–2개의 지역 ID를 방문 순서대로 보존한다. 최초 선택 또는 추가 선택은 보상 이력이 처리된 경로 끝에서만 가능하다. 첫 지역은 공통 3전투 보상 처리, 두 번째 지역은 그 뒤 첫 보스까지 7전투의 보상 처리가 필요하다. 저장 불러오기에서도 이 문턱을 검사하며, 미래 지역을 미리 넣거나 지역을 바꾸거나 순서를 뒤집은 이력을 거부한다.
- v1–v6의 런 ID·생성 시각·덱·교체 횟수·고정 후보·처리 영수증을 보존한다. v6의 첫 지역 완료 저장은 두 번째 지역 선택부터 이어가고, 보스 보상이 남아 있으면 먼저 처리한다. v6에 지역 두 개를 넣은 잘못된 저장은 허용하지 않는다. 불러오기는 저장을 다시 쓰지 않으며 다음 정상 저장부터 v7로 기록한다.
- 지역 이동은 기존 선택 토큰의 런 ID·보상 sequence·덱 revision·지문을 다시 검사한 뒤 경로만 한 번 저장한다. 이미 방문한 지역, 진행 중 재선택, 오래된 버튼, 저장 실패는 경로를 변경하지 않는다. 지역 선택 자체는 덱·보상 이력·노드 수를 늘리지 않는다.
- 지역 전투 ID는 기존 `${regionId}-1/2/3/boss`를 유지한다. 두 번째 지역의 전역 `battleIndex`는 7–10이며, 전투 영수증 검증과 다음 전투 계산은 선택한 지역 전체를 순서대로 잇는다. `nodeIndex`는 실전 영수증 수, `currentZone`은 경로 마지막 지역으로 재구성한다. 수동 테스트 보상은 이 전투 번호를 앞당기지 않는다.
- 두 번째 지역도 23절의 적 구성·필드·기본 코어 규칙을 사용한다. 보상은 실제 전투가 열린 두 번째 지역의 `action-tags-region-v1` 성향을 적용하며, 첫 지역의 후보나 받은 카드를 다시 계산하지 않는다. 지역 방문 순서에 따른 별도 적 강화와 보스 경제는 아직 미확정이다.
- 진행 화면은 전체 방문 경로와 다음 상대를 보여주며, 두 번째 선택에는 미방문 지역 버튼 세 개만 표시한다. 보상 처리 전에는 선택·전투를 잠근다. 결과창과 전투 안내는 노드 ID·지역·전역 번호로 상대를 확인하므로 두 번째 지역 보스도 보스로 표시한다.
- 검증: `tests/m11a-multi-region.mjs`에서 12개 방문 순서의 v6 복원·실제 선택 버튼·덱/영수증 보존, 두 번째 지역 48개 전투 시작과 승리/패배/무승부/저장 실패 결과, 중복/다른 지역 결과, 잘못된 경로와 보상 지역, 마지막 보상 이후 종료 문턱을 검사한다. 전체 121개 회귀가 통과했다. 전투 결과는 테스트에서 주입하며 이 검사는 11연전의 승률·난도·플레이 시간 측정이 아니다.

두 번째 지역 이후 널워드와 최종 보스·런 완료는 아래 25절로 이어진다. 상점/이벤트, 지역 방문에 따른 난도와 경제는 기존 미확정 항목으로 유지한다.


## 25. 널워드와 최종 보스·런 완료 v1 — 저장 v8

2026-09-02 구현. 두 분기 지역의 전투와 보상을 모두 마치면 널워드로 이어진다. 현재 경로는 `공통 3전투 → 첫 지역 4전투 → 두 번째 지역 4전투 → 널워드 3전투 → 마지막 보상 처리 → 런 완료`다. 14전투는 플레이 가능한 프로토타입 범위이며, 최종 런 길이와 난도·경제를 확정하는 수치는 아니다.

| 14번째 | `null-ward-final` | 최종 보스 공백 관리자 | 16 + 1 | 교차 선로 |

- 널워드는 `regionPath`에 넣는 세 번째 선택지가 아니다. 분기 지역 두 곳 뒤 이어지는 고정 후반 경로이며, 첫/두 번째 지역 선택 화면에는 등장하지 않는다. 전투 ID·인덱스(11–13)·지역을 검증하고, 두 번째 보스 보상이 남아 있으면 널워드 전투를 발급하지 않는다.
- 상대는 정규 29슬롯 + 조커 1장과 기본 코어 3×60, 시작 손패 8장, 공용 전투 규칙을 사용한다. 위조범·밀수업자·샛길·도플갱어의 판정 변형, 응급 보호구/연결자와 복사기의 효과 복제, 독침/절단선 등의 간섭으로 구성한다. 후반 적 구성은 플레이어 덱 슬롯이나 해금 목록을 변경하지 않는다.
- 널워드 보상 성향은 `규칙 변형 3 / 상태 2 / 상대 조합 1`이며 기존 지역 가산점 상한 +6, 기반 보강 중립, 새 테마 후속 카드 제한을 유지한다. 같은 슬롯의 해금 카드만 후보로 삼고, 없는 카드나 전용 테마를 생성하지 않는다. 널워드 영수증에는 `action-tags-region-v1`과 `regionId: null-ward`가 필요하다.
- 최종 보스도 승리 시 후보를 고정하고 마지막 1장 수령 또는 건너뛰기를 제공한다. 이때는 아직 `prepared`이며 재접속해도 같은 마지막 보상을 보여준다. 마지막 보상을 처리할 때 카드 교체/영수증/`status: completed`/ISO 완료 시각 `completedAt`를 한 번에 저장한다. 후보가 0장이면 건너뛰기로 정상 완료할 수 있다.
- v8 불러오기는 마지막 노드까지 유효한 영수증과 마지막 보상 처리 여부를 검사한다. 완료 플래그만 넣기, 완료 시각 누락/오염, 마지막 보상 처리 전 완료, 완료 뒤 추가 영수증, 다른 지역/노드 결과를 거부한다. 중복 결과나 수령 버튼은 완료 시각·보상·덱을 다시 변경하지 않는다. 저장 실패는 마지막 보상을 미처리 상태로 남긴다.
- 기존 v1–v7 저장의 런 ID·스타터·덱·교체 횟수·고정 후보와 영수증을 보존한다. v7의 11승 저장은 널워드부터 이어가고, 보스 보상이 남아 있으면 먼저 처리한다. 이전 스키마에 새 후반 영수증이 들어 있는 손상 저장은 거부한다. `currentZone`은 실제 진행 위치로 재구성하며 보상 처리 전에는 해당 보상을 준 전투의 지역을 유지한다.
- 완료 화면은 스타터, 14전투 승리, 전체 방문 경로, 최종 순수/네임드 수와 교체 횟수, 보상 수령/건너뛰기 횟수, 완료 시각을 보여준다. 완료 뒤 실전 노드·수동 테스트 보상 발급은 닫고 최종 덱 실험전과 새 런 시작을 제공한다. 최종 덱 실험전의 승패는 완료 기록을 변경하지 않는다.
- 완료 기록은 현재 런 저장 키에 유지한다. `새 런 시작` 또는 런 덱 지우기를 실행하면 기존 현재 런을 교체/삭제한다. 여러 런의 완료 아카이브와 메타 보상은 아직 별도 구현하지 않았다. 일반 클리어·캐릭터 레벨·해금·M12 표본에는 계속 반영하지 않는다.
- 검증: `tests/m11a-run-completion.mjs`에서 12개 지역 순서, 36개 후반 전투 시작/승리/패배/무승부/저장 실패 결과, 실제 마지막 수령/건너뛰기 UI와 완료 저장, v7 복원, PURE·빈 후보 풀, 중복 결과, 손상 완료 기록, 완료 덱 실험전·새 런 격리를 검사한다. 새 적 3종의 96개 손패에서 공용 AI의 합법 조합 선택을 확인했고 전체 122개 회귀가 통과했다. 전투 결과는 테스트에서 주입하며 14연전 승률·체감 난도·플레이 시간은 아직 검증하지 않았다.

이제 후속 범위는 상점·이벤트와 맵 구성 확장, 완성된 런 경로의 플레이테스트를 통한 난도·보상 경제 조정이다.


## 26. 완료 런 아카이브 v1

2026-09-02 구현. 25절의 최종 보상 처리로 런이 `completed`가 된 뒤, 현재 런 저장과 별개인 `rummyDuelRoguelikeRunHistoryV1`에 완료 기록을 보관한다. 새 런을 시작해 현재 draft가 교체되어도 이전 클리어 요약과 최종 덱은 남는다.

- 아카이브는 `runId` 기준 멱등 저장이다. 완료 화면이 다시 렌더되어도 같은 런을 중복 추가하거나 저장 횟수를 늘리지 않는다. 최신 기록이 앞에 오며 최대 24개를 보존한다.
- 한 기록에는 완료 시각, 스타터 ID/표시명, 두 분기 지역 ID/표시명, 실전 승리 수, 보상 수령/건너뛰기 수, 최종 덱 revision, 네임드 수, 최종 30장 `runDeck` 청사진과 덱 지문, 각 보상 sequence/source/status/선택 카드/전투 노드를 저장한다. 따라서 이후 통계·리플레이/최종 덱 재사용 기능의 입력으로 확장할 수 있다.
- 저장값을 읽을 때 날짜·중복 runId·보상 sequence/status·전투 영수증 수·최종 덱 정규화·덱 지문을 다시 검사한다. 손상된 아카이브는 현재 런 진행을 깨뜨리지 않고 빈 기록처럼 취급한다.
- 런 완료 저장과 아카이브 저장은 서로 다른 키다. 마지막 보상과 `completed` 상태 저장이 먼저 성공한 뒤 UI에서 아카이브를 보장하며, 아카이브 쪽 저장 실패가 이미 확정된 런 완료를 롤백하지 않는다. 다음 완료 화면 렌더에서 다시 보관을 시도한다.
- 완료 화면은 누적 완료 횟수와 최근 스타터/경로/승리/최종 네임드 수/교체 횟수를 표시한다. 새 런 진행 중에도 기존 완료 기록이 있으면 같은 요약을 진행 화면 아래에 표시한다.
- 일반 대전의 `totalClears`, 캐릭터 레벨/해금, 덱빌더 진행도 및 별도 M12 표본 저장은 건드리지 않는다. 메타 보상은 계속 미확정이다.
- 검증은 `tests/m11a-run-completion.mjs`의 12개 지역 순서 전체 완료 루프에 아카이브 저장·최종 덱/14전투 영수증·경로 일치·재렌더 중복 방지를 추가해 수행한다.


## 27. 런 경로 지도 v1

2026-09-02 구현. 이미 플레이 가능한 14전투 프로토타입을 새로운 규칙 없이 읽기 쉽게 보여 주는 진행 지도다. 지도는 `roguelikeBattleProgress()`와 `roguelikeRunRoute()`의 결과만 사용하며 런 저장을 직접 수정하지 않는다.

- 공통 시작, 실제로 선택한 1·2지역, 널워드 노드를 방문 순서대로 가로 스크롤 카드로 표시한다. 아직 고르지 않은 지역은 지도에 임의로 확정하지 않고 `지역 1/2 선택` 관문 하나만 표시하며 기존 지역 선택 UI가 실제 선택을 담당한다.
- 전투 상태는 `보상 처리 완료 / 승리·보상 대기 / 다음 전투 / 잠김` 네 단계로 분리한다. 전투 승리 영수증이 생겼지만 해당 카드 보상이 pending이면 그 노드는 완료색으로 넘기지 않고 별도 보상 대기 상태를 유지한다.
- 완료 런은 확정된 14개 전투를 모두 완료로 표시하고 헤더를 `런 완료`로 전환한다. 진행 중에는 누적 승리 수와 현재 프로토타입 전체 전투 수를 함께 보여 준다.
- 지도는 읽기 전용이다. 전투 시작, 보상 수령/건너뛰기, 지역 선택, 덱 교체, 저장 함수는 지도 자체에서 호출하지 않는다. 따라서 기존 전투/보상/지역/완료 계약과 일반 진행도·M12 표본은 바뀌지 않는다.
- 상점·이벤트·엘리트 노드 위치나 비율은 아직 확정하지 않는다. 후속 맵 확장에서 실제 노드 종류가 추가되면 같은 상태 표현을 확장하되, 이번 v1을 경제/런 길이 확정 근거로 사용하지 않는다.
- `tests/m11a-route-map.mjs`는 현재·잠금, 승리 후 보상 대기, 지역 선택 관문 2회, 완료 상태와 읽기 전용 조건을 회귀로 고정한다.
