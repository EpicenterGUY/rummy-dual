## 보험설계사 H9

같은 조합의 내 카드가 상대의 절단·탈취 대상이 되면, 이 카드에 귀환이 없을 때 해당 간섭을 1회 무효로 하고 자신에게 불안정 1을 부여한다. 카드당 전투 1회만 발동한다.

기존의 즉시 소모를 불안정으로 교체했다. 간섭을 막는 순간 카드나 조합을 이동시키지 않고, 소모·회수·균열 이벤트도 만들지 않는다. 따라서 보험설계사를 즉시 빼면 조합이 불법이 된다는 이유로 보험이 실패하지 않는다. 자기 자신도 같은 조합의 내 카드에 포함한다.

합법적인 절단·탈취 대상인지 확인한 뒤 카드 보호 → 상대 조합의 보호 → 보험 → 기존 엄폐 교대 순서로 처리한다. 보험은 조합 슬롯 소유자나 원주인이 아니라 대상 카드의 현재 제어자를 기준으로 찾는다. 내 카드에 내가 하는 이동에는 보험을 쓰지 않는다. 보험 출처가 침묵 중이거나 귀환을 보유하거나 이번 전투에 이미 보험을 썼다면 발동하지 않는다. 먼저 쓴 다른 보호는 보험의 사용 횟수를 소모하지 않는다.

보험의 계약은 **절단·탈취**다. 침묵·불안정 같은 상태 부여는 카드/조합 보호와 엄폐 교대 관문을 사용하지만 보험을 발동하지 않는다. 6차의 일반 간섭 관문에 보험이 함께 적용되던 부분을 최종 H9 설계에 맞췄다.

전투 사용 기록은 물리 카드와 전투 ID에 묶인다. 회수·보존·덱 순환·버림패 이동·소유권 변경으로 사용 기록을 지우지 않는다. 실제 플레이어/CPU의 절단·탈취 경로가 같은 함수를 사용한다.

## 불안정의 수명

불안정은 활성 카드에 부여하는 양의 정수 카운트다운이다. 자기 손패/공개 카드와 공통 적대 간섭 관문을 통과한 상대 공개 카드가 대상이다. 잘못된 값, 비활성 영역의 대상, 전투 종료 뒤 부여는 거부하며 보호 횟수도 쓰지 않는다.

첫 부여 당시 제어자를 기록한다. 그 제어자의 턴 종료마다 1 감소한다. 자기 턴에 얻은 1은 그 턴 종료, 상대 턴에 얻은 1은 다음 자기 턴 종료에 만료한다. 재부여는 남은 수치 중 작은 값만 채택하고 기록한 제어자와 다음 감소 시점을 바꾸지 않는다. 손패↔공개 이동, 공개 조합 사이 이동, 제어권 변경도 타이머를 초기화하지 않는다.

덱·버림패·소모패에 들어가는 순간 불안정을 제거한다. 정비·순환·덱 위 예약·개별 소모·조합 정리·전체 재순환을 공통 정리 함수로 연결했으며, 바로 재획득해도 만료한 타이머가 살아나지 않는다. 승리·패배·교착 무승부도 모든 영역의 불안정을 제거한다.

## 만료와 조합 유효성

턴 종료는 기존 고정 만료 다음에 불안정을 처리하고, 그 뒤 폭발과 기존 정리를 진행한다. 침묵 만료는 기존처럼 마지막이다. 이미 부여된 불안정은 침묵·고정·보호로 정지하지 않는다.

먼저 해당 종료의 타이머를 모두 감소시키고, 0인 상태와 만료 메타데이터를 지운 뒤 이동을 해결한다. 같은 종료는 한 번만 처리한다. 처리 도중 반응으로 새로 생긴 불안정은 다음 기록 제어자의 턴 종료부터 감소시켜 재진입·즉시 반복을 막는다.

| 만료 위치 | 결과 |
|---|---|
| 손패 | 현재 제어자의 소모패로 이동. 버리기·회수·러미 행동으로 취급하지 않음 |
| 공개 조합, 만료 카드를 뺀 결과가 같은 종류의 합법적인 3장 이상 조합 | 해당 카드만 소모. 런 체인은 소모한 장수만큼 감소하고 최소 0 |
| 공개 조합, 남은 결과가 불법 | 조합 전체를 한 번 정리. 귀환과 기존 정리 목적지·명시적 보존 규칙을 유지 |
| 이미 덱·버림패·소모패 | 불안정만 제거하며 다시 소모하지 않음 |

같은 조합에서 동시에 만료하는 카드들은 함께 검사한다. 남은 결과가 합법일 때 모든 해당 카드를 이동한 뒤 각 소모 이벤트를 발행한다. 그렇지 않으면 정리 한 번으로 해결하며, 그 정리로 돌아온 만료 카드를 같은 종료에 다시 소모하지 않는다. 아직 수치가 남은 다른 귀환 카드는 감소된 타이머를 유지한다.

개별 소모는 기존 `onMeldSpend` → 균열·표적/접전 갱신을 사용한다. 전체 정리는 개별 소모 이벤트와 균열 피해를 만들지 않는다. 생성·회수·스위치 반환 권한을 보충하지 않는다. 균열로 전투가 끝나도 이미 이동한 카드와 보드는 완결된 상태이며, 폭발이나 상대 턴으로 계속 진행하지 않는다. 이 경로에서 종료 화면 상태가 `wait`로 덮이던 턴 종료 처리도 수정했다.
